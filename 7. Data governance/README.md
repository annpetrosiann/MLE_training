# 📊Data Version Control (DVC) Pipeline Example

This project  demonstrates usage of [DVC](https://dvc.org/) to track data, define reproducible pipelines, share data using remote storage, and track and compare experiment metrics.

## Project Structure
```
├── .dvc/                      
│   ├── .gitignore
│   └── config
├── data/             
│   ├── raw/                  # Contains original input data tracked by DVC
│   ├── processed/            # Generated by dvc repro
│   ├── plots/                # Generated by dvc repro
├── scripts/                     
│   ├── preprocess_data.py    # Cleans and preprocesses data
│   ├── train.py              # Trains a model and logs metrics
│   ├── visualize.py          # Generates plots and visualizations
├── dvc.lock                  # Snapshot of pipeline execution state
├── dvc.yml                   # Pipeline definition
├── requirements.txt          # List of dependencies required to run the project.
└── README.md
```

## 🚀 Initial Setup

### 1. Initialize Git and DVC
```bash
git init
dvc init
```
You should now see:

✅ .dvc/ directory created.

✅ .gitignore updated to ignore data files.

### 2. Tracking Data with DVC
After initilization, you can add your dataset to DVC tracking by running:

```bash
dvc add data/raw/winequality-red.csv
```
How it would look like in data directory:

```
data
└── raw/
    ├── winequality-red.csv         # actual data (tracked by DVC, not Git)
    ├── winequality-red.csv.dvc     # DVC metadata (tracked by Git)
    └── .gitignore                  # ignores raw data from Git
  ```
> 📌 **Note**:
> 
> Every time you run dvc add, DVC automatically creates or updates a .gitignore file in the corresponding folder to ensure that large data files are not tracked by Git but are tracked by DVC instead.



### 3. Configuring Remote Storage (Google Drive Example)
  Install Google Drive support:

  ```bash
pip install "dvc[gdrive]"
```
  Configure the remote (see `.dvc/config`):
```bash
dvc remote add -d gdrive_remote gdrive://<your-folder-id>
dvc remote modify gdrive_remote gdrive_client_id <client_id>
dvc remote modify gdrive_remote gdrive_client_secret <client_secret>
```
  Push your data to the remote:
```bash
dvc push
```

### 4. Authorization (One-Time Google Sign-In)

When pushing or pulling data for the **first time**, DVC opens a **browser window** asking you to authorize access to your Google Drive.

1. Log in using the **Google account** that has access to the remote folder.
2. Grant the required permissions.
3. After authorization, you can **push** and **pull** data without needing to reauthorize (unless your token expires).

And now your data is being tracked by DVC and stored in Google Drive.

## ⚙️ DVC Pipeline

DVC pipelines allow you to define **multi-step data processing workflows** that are **versioned** and **reproducible**.

### What is `dvc.yaml`?
`dvc.yaml` is a file that **describes your pipeline stages**, their **commands**, **inputs**, and **outputs**.  DVC uses this file to **reproduce** the workflow when you run `dvc repro`.

🔍 Look at our actual `dvc.yaml` to see how we define pipeline stages such as preprocessing, training, and visualization.

Each stage runs a **Python script** located in the `scripts/` directory:

- **scripts/preprocess_data.py** – handles data cleaning and preprocessing.
- **scripts/train.py** – trains a model and logs the results.
- **scripts/visualize_data.py** – generates visualizations based on processed data.

### What is `dvc repro`?
`dvc repro` reproduces the pipeline by running all stages in the correct order. It skips stages where inputs and outputs have not changed (using checksums for tracking). This ensures efficient and consistent pipeline execution.

To run the pipeline:

```bash
dvc repro
```

### What is `dvc.lock`?

The `dvc.lock` file is automatically generated and updated when you run `dvc repro`. It acts as a **snapshot** of your pipeline’s state at a specific moment in time. It records:

- The **exact commands** run for each stage.
- The **dependencies** (input files and scripts) used.
- The **outputs** generated.
- The **hashes/checksums** of all inputs and outputs.

This ensures that your pipeline is **fully reproducible** and others (or your future self) can **re-run** the exact same version of the pipeline and get the same results.

🔍 See the actual `dvc.lock` file in this repo for a real example of how DVC captures pipeline details.

## 🛠️ How to Reproduce This Project

1. **Clone the Repository**
    ```bash
    git clone https://github.com/yourusername/yourrepo.git
    cd yourrepo
    ```

2. **Install Python Dependencies**
    ```bash
    pip install -r requirements.txt
    ```

3. **Pull the Data from Remote Storage**
    ```bash
    dvc pull data/raw/winequality-red.csv.dvc
    ```
    > **Note:**  
    Here, you **only pull the raw data**, _not the processed results_.  
    This allows you to **re-run the pipeline from scratch** using `dvc repro` and validate that everything works correctly.

4. **Run the Full Pipeline**
    ```bash
    dvc repro
    ```
    This will reproduce all pipeline stages. Generate new outputs such as processed data, metrics, and visualizations. Update the `dvc.lock` file.

5. **Push Results to Remote Storage (Optional)**
    ```bash
    dvc push
    ```
    This will upload **all newly generated results** (processed data, metrics, etc.) to your **remote storage** (Google Drive in this case).

6. **View and Compare Metrics**
    - Show current metrics:
      ```bash
      dvc metrics show
      ```
    - Compare metrics with previous runs:
      ```bash
      dvc metrics diff
      ```

> 📌 **Note:**  
> Metrics are stored in `metrics.json`, which is automatically updated after running `train.py`.  
> This file is tracked by DVC using `dvc metrics`, allowing you to compare model performance across different pipeline runs.
